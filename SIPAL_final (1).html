💾 Persistência da base. A base carregada é salva localmente com IndexedDB, suportando arquivos grandes (sem o limite de ~5 MB do armazenamento simples) e permanecendo disponível após atualizar a página (F5) e após fechar e reabrir o navegador neste mesmo dispositivo/navegador. Importante: por rodar 100% no navegador (client-side, compatível com firewall corporativo), esse armazenamento é local a cada computador — ele não sincroniza automaticamente a base entre computadores/usuários diferentes. Para uma base centralizada e compartilhada entre todos os dispositivos, é necessária uma camada de servidor (endpoint compartilhado). Isso já pode ser habilitado na aba 🌐 Base Central (GitHub) acima (Cloudflare Worker + R2, ou publicação via GitHub), mantendo o IndexedDB como cache e fallback offline.

☁️ Sincronização centralizada via Firebase (opcional) — publica a base para todos os colaboradores, em qualquer dispositivo, em tempo real. Funciona 100% no navegador, com arquivo HTML único: use o Firebase Realtime Database (plano gratuito). Informe abaixo a URL do Realtime Database (o campo databaseURL do seu projeto, ex.: https://SEU-PROJETO-default-rtdb.firebaseio.com). O segredo do banco é opcional e só é necessário para publicar/alterar a base quando as regras de escrita estiverem restritas; em modo de teste, deixe-o vazio. O Administrador publica a base uma vez e ela passa a ser distribuída automaticamente; cada dispositivo mantém uma cópia local (IndexedDB) como fallback offline. Obs.: se o firewall corporativo bloquear *.firebaseio.com, teste pela rede móvel (4G).

A leitura da base é pública (todos os colaboradores) e a escrita exige o token definido no Worker (variável SIPAL_TOKEN). A base fica no bucket R2 — sem limite prático de tamanho e sem custo de banda no plano gratuito.
